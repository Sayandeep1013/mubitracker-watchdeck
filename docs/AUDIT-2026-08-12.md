# Mubitracker — Full Audit, 2026-08-12

Method: four parallel diagnostic passes — mobile QA on a real Android device (Maestro + adb + logcat),
web QA against production (Playwright, two accounts), spec-vs-code audit (14 specs), and a deck-engine
code analysis — plus direct queries against the live Supabase database.

Reference user for "heavy account" behaviour: `rein` — 283 tracked items (123 watched, 149 haven't, 11 watch later).

---

## 0. Headline corrections to prior assumptions

| Assumption | Reality |
|---|---|
| "The app feels slow everywhere" | **Mobile is not slow.** Deck advance is instant (prefetched); API 0.25–0.85s warm. Web card advance median **275ms**. The slowness is concentrated in **filtered deck loads (~9s)** and **title search (~6.2s)**. |
| "`/review-later` takes ~5s" | Now **196ms** to first meaningful render — fixed by the Vercel region move to `bom1`. |
| "The deck repeats titles" | **Not for new accounts** — verified 30/30 unique on web, 12/12 on mobile. It is a **heavy-account** failure: the reachable pool is ~400 titles and `rein` has consumed 283. |
| "Friend search is broken" | The **API flow works end-to-end** (request → accept → compare). Discovery is blocked by a **missing privacy-settings UI**, not by search logic. |

**Mobile ↔ web parity** (spec `08` requires parity)

Missing entirely on mobile: **filters** (all of them, incl. presets), **Watch Later** (no gesture, action, screen, or tab), **swipe-down / Review Later gesture**, **fallback action buttons** (gesture-only = accessibility violation), **sticky action state**, **friends** (zero UI — 11 client methods unused), **`/about` TMDB attribution** (licensing gap), **toasts**.
Degraded on mobile: undo is 1-deep vs web's 20; search lacks Watch/Review Later + type/language filters; collection lacks tabs/filters/sort/search/pagination; profile lacks import, delete account, privacy, stats; review lacks spoiler toggle.
**Conflicting gesture:** ↑ = Watch Later on web, **Review Later** on mobile.

## 3. P2 — Minor / cosmetic

- Anime filter force-overrides an explicitly chosen language (`generate.ts:89`) — Korean/Chinese animation unreachable.
- Multi-language selection silently ignored (`generate.ts:91` applies only when exactly 1 selected).
- Duplicate friendship rows possible — reverse-**accepted** not checked (`friends/route.ts:93-151`).
- Block requires an existing friendship row → cannot block a stranger from search.
- Cannot **unblock** (no route) — block is irreversible.
- Mobile session in `AsyncStorage`, not `SecureStore` (spec `08` requires SecureStore; `expo-secure-store` is installed but unused).
- Invalid Tailwind classes: `text-neutral-00`, literal `text-neutral-????00` (`profile/page.tsx`).
- TMDB attribution logo is a broken image (`ERR_BLOCKED_BY_ORB` on `/about`).
- Review-later empty state names the wrong key (says ↑, actual is ↓).
- Import errors always report "Invalid JSON" regardless of cause.
- Collection status chips render lowercase next to capitalized siblings.
- Mobile: no loading/empty states on Collection; no stats on Profile; Export is a dead end (Alert only, no file/share); login has no `KeyboardAvoidingView`; search rows lack poster placeholder and year/type.
- Notifications: marks **all** read on bell click; toast has no Accept action; endpoint path is `POST /notifications` not the specced `/notifications/read`.

## 4. Pipeline & engineering gaps

- **No analytics/instrumentation at all** — the headline success metric (2–4s per classification) is unmeasurable.
- **No E2E tests.** CI runs typecheck + shared unit tests + web lint + web build only; no mobile bundle check, no Playwright/Maestro run, no API contract tests.
- **No caching anywhere** — no `revalidate`, no `unstable_cache`, no in-flight dedup; TMDB rate-limiting is a 35ms per-instance gate that is meaningless on serverless.
- **No TMDB-down fallback for the deck** — throws → 500. (Search degrades correctly.)
- **Dead code:** `export async function GET_MEDIA` (not an HTTP verb; ignored by Next). Unreachable endpoints: `/recommendations`, `/friends/[id]/collection`, `/friends/[id]/profile`. Unused shared exports and client methods.
- **`media` is a write-only cache** — never queried as a candidate source, so no local ranking/sampling is possible.
- **Docs badly stale:** claims 11 specs (14 exist), 2 migrations (5 applied), "no git repo" (repo + remote + CI exist), "Expo SDK 52 scaffolded" (SDK 54.0.36 / RN 0.81.5 / React 19 / Reanimated 4), Vercel described prospectively (live), missing `notifications` table, several wrong API paths.

## 5. What works — do not regress

Signup / login / logout / auth guard / middleware redirects, and all auth error messaging.
Deck: all gestures + keyboard (←/→ select, ↑/↓/Enter act, Z undo, F filters), sticky action, on-screen buttons, undo for left/right swipes, **30/30 unique titles across 30 web classifications and 12/12 on mobile**, instant advance.
Filters: respected server-side; **Watched+Unwatched together now returns a populated deck** (previously-fixed bug holds); presets save/persist/re-apply.
Collection: tabs, status, sort, search, list/grid all filter correctly server-side.
Watch Later / Review Later populate from deck actions; review body persists and removes the item from pending.
**Full two-account friend flow: request → bell + Incoming(1) → Accept → mutual**, plus Compare and Their Deck.
Profile stats accurate; Export downloads valid JSON; Import works on well-formed payloads.
IMDb button opens the correct real `imdb.com/title/tt…` page on both clients.
Zero console errors on every web page; zero JS errors in mobile logcat across the whole session.
